# IwaraFlow

Android 原生的 Iwara 竖屏短视频流播放器，提供类似短视频 App 的连续浏览体验。

## 功能

### 视频流

- 四个版块：推荐 / 最新 / 流行 / 人气
  - **最新**：Iwara 官方 `sort=date`
  - **流行**：Iwara 官方 `sort=trending`
  - **人气**：Iwara 官方 `sort=popularity`
  - **推荐**：本地推荐算法，见下文
- 上滑下一条、下滑上一条，滑到末尾自动加载更多；推荐页翻页继续使用推荐候选，候选用完重新生成
- 播放结束自动进入下一条（可关闭）
- **刷新推荐时排除已看视频**：只在生成新的推荐列表时过滤，不在滑动过程中自动跳过
- **可播放验证**：视频进入列表前先解析实际 CDN 播放源并做 Range 探测，确认能返回媒体数据才显示
- **首屏边验证边上屏**：最先通过验证的几条立即播放，其余在后台继续验证并按原顺序补入列表
- 单条视频源和单个榜单请求都有时间预算，不会拖住整页

### 播放器

- AndroidX Media3 / ExoPlayer，默认最高可用画质，可手动切换清晰度
- 单击播放 / 暂停
- 暂停时在视频标签下方显示可拖动的进度条，同时隐藏信息栏和操作栏；播放时恢复。进度条右上方显示剩余时长（`-m:ss`），拖动时屏幕下方居中显示“当前位置 / 总时长”
- 暂停时进度条上方、左下角显示控制行：后退 N 秒 / 播放三角 / 前进 N 秒。N 在设置中选择（5 / 10 / 15 / 30 / 60，默认 15），播放三角可在设置里关闭
- 横屏视频画面略高于屏幕中央（抬起卡片高度的 24%），竖屏视频铺满
- 按住画面约 0.45 秒临时 2× 加速，松手恢复，加速时显示 `2× 加速中`；加速中手指允许挪动约 48dp，且翻页控件不再截走这根手指，长按多久都不会中途掉速
- 点赞 / 收藏 / 双击点赞的动画播在点击的位置：按钮上或手指落点
- 画中画（PiP），可设置切到后台自动进入
- 分享：应用内分享面板列出能接收链接的应用，点选后直接拉起该应用的分享入口（QQ 等应用以自己的小窗卡片盖在视频上，视频继续播放）；另有复制链接和系统选择器
- 播放地址过期或出错时自动重新解析并从原位置继续，最多重试 2 次
- 播放卡死看门狗：时间轴长时间不前进时自动重建播放源
- 全 App 单一播放所有权：进入其它视频页面时立即停止上一页面的播放器

### 简介与评论

- 底部半屏面板有「简介」「评论」两个页签：点视频标题或标签行打开简介，点右侧评论按钮打开评论；在面板内容区左右滑动可切换页签；主页、作者页、搜索页、收藏 / 已下载 / 历史的播放流都有
- 简介页显示标题、作者、日期、播放 / 点赞数、标签和作者写的正文；本地列表里没带简介的视频打开时补拉一次详情
- **自动翻译**：面板打开时，外语的简介和评论自动翻成中文，正文上方一行小字标明“翻译自 × 语”，点它切回原文。原文已是中文或没有文字（纯表情、数字）的不翻、不显示这一行；翻译失败在同一位置显示原因，点击重试。面板没打开时不发请求，结果按原文缓存，同一条不会翻第二次
- **翻译服务可选**（设置 → 翻译）：默认谷歌翻译免费网页接口（`translate_a/single`，无需密钥）；内置 DeepL（免费版 Key 自动走 api-free）、微软 Azure Translator（Key + 区域）、百度翻译开放平台（APP ID + 密钥，MD5 签名）、LibreTranslate（服务器地址 + 可选 Key）、AI 翻译（内置 OpenAI、DeepSeek、通义千问、Kimi、智谱 GLM、硅基流动、Gemini、xAI、OpenRouter 九家服务商，接口地址和模型已预设，只需填 API Key；选“自定义”可接任何兼容 OpenAI 聊天接口的中转站：地址写到 `/v1` 即可自动补成 `/chat/completions`，模型默认 `gpt-4o-mini`。请求不带 temperature 等采样参数，推理类模型也能用；失败原因写入诊断信息）；也可以自定义接口：地址模板（`{text}`、`{target}` 占位）、GET / POST、请求体模板、请求头、译文和源语言的字段路径（`data.translations.0.text` 这样的点分路径，留空按常见字段名猜）。换服务后翻译缓存清空
- 右侧操作栏的评论按钮打开评论页签，内容为 Iwara 官方评论
- 支持回复：发送到 Iwara 官网，与网页端回复等价；「共 N 条回复」原地展开 / 收起
- 面板顶边对齐画面底边：横屏视频面板接在画面下方，竖屏视频画面按比例缩到顶栏与面板之间
- 面板打开时播放不受影响；点击画面、翻页、返回键、进入小窗均关闭面板；按住顶部把手下拖也可收起
- 写评论时输入层贴在键盘上方、盖在面板之上，页面和面板不收缩；点空白处收起键盘，未发送的文字保留为草稿
- 未登录时点输入框会先弹出登录框
- 点评论者的头像或名字进入其主页；没有作品的用户只显示资料，作品列表标明“没有作品”

### 作者主页 / 关注 / 好友

- 点击作者名进入作者主页，分页展示该作者作品并显示真实缩略图
- 简介默认显示三行，点击展开全文，滑动作品列表时收起
- 不可播放的作品保留在列表中，并在缩略图上标出原因（仅限好友 / 无权限 / 处理中 / 资源失效）
- 点击可播放作品后进入仅包含该作者作品的竖滑播放流；滑到最后一条再往上拉、或最后一条播完时提示“没有更多视频了”，不绕回开头
- 主菜单的浏览历史 / 我的收藏 / 已下载同样是列表 + 竖滑播放流：点一条从它开始播，上滑是列表里的下一条，到底有同样的提示；已下载的直接放本地文件，其它在线播放；评论、简介、小窗、分享、下载与作者页播放流一致
- 返回顺序：作者播放流 → 作者作品列表 → 进入作者页的页面；系统返回键、全面屏手势和页面按钮共用同一逻辑
- 关注 / 取消关注，好友申请 / 取消申请 / 删除好友，状态与 Iwara 官方同步
- 主菜单「已关注用户」按服务端总数翻页读取，关注数超过 50 也会全部列出
- 作者主页可分享作者名字、简介和主页链接

### Iwara 账号

- 登录：`/user/login` → `/user/token`；Token 使用 AndroidX Security 加密存储，密码不落盘
- 注册：登录框的“注册”在应用内打开官网注册页 `www.iwara.tv/register`（WebView），人机验证和邮箱确认由官网完成，注册成功即为官网账号；站内链接留在页面里，站外链接交给系统浏览器，也可一键改用浏览器打开
- 点赞：`POST / DELETE /video/{id}/like`
- 点赞列表：`/favorites/videos`，后台完整翻页同步并计入已看
- 关注、好友关系同步

### 收藏与浏览历史

- **爱心** = Iwara 官方点赞，同步到服务端；**五角星** = 本机收藏，存在本地 SQLite。两者互不影响
- 浏览历史记录最后播放位置、时长和是否基本看完
- 独立 `seen_videos` 表永久记录推荐系统使用的“已看视频 ID”，数据库升级时自动迁移
- 我的收藏、浏览历史、已下载共用同一套卡片列表布局

### 搜索与下载

- 独立的搜索结果页，三个标签页：
  - **视频名**：`/search?type=videos&query=...`
  - **标签**：`/videos?tags=...`；空格、逗号、顿号分隔的多个词表示同时带这些标签，无结果时按下划线、连写当作单个标签重试
  - **作者名**：`/search?type=users&query=...`，显示头像并可进入作者主页
- 视频结果保留不可播放作品并显示原因，可播放的在结果内竖滑播放
- 下载走 Android DownloadManager，下载前可选清晰度
- **已下载**页面：App 记录下载过什么，页面向系统下载器查询实际状态
  - 已完成的直接播放本地文件；仍在下载 / 失败的在卡片上标出；系统里已查不到的退回在线播放
  - 同一视频的不同清晰度各算一条，重新下载同一清晰度覆盖旧记录
  - 打开页面时自动补录系统下载器中本应用发起过、但本地表没有的下载（按文件名 `<标题>_<视频 id>_<清晰度>.mp4` 从右往左解析）

### 应用内更新

- 启动后后台检查 GitHub 最新 Release，约 6 小时一次；主菜单可手动检查
- 显示当前版本、新版本号和更新内容；下载固定签名的 `IwaraFlow-signed.apk` 后拉起系统安装
- Android 8+ 未授权“安装未知应用”时自动进入授权页，返回后继续安装

### 菜单与设置

主菜单：登录（含注册入口）/ 退出、浏览历史、我的收藏、已下载、已关注用户、设置、检查更新、重新加载当前流。

设置页：

| 分组 | 内容 |
| --- | --- |
| 推荐 | 刷新推荐时排除已看视频；老片穿插间隔（关闭 / 8 / 12 / 16 / 24） |
| 播放 | 播放完毕自动进入下一条；切到后台自动进入画中画；暂停时显示播放三角；前进 / 后退秒数 |
| 默认清晰度 | 对之后播放的视频生效；当前视频用右侧画质按钮切换 |
| 网络 | 手动代理（HTTP / SOCKS，主机 + 端口），进程级生效，播放器、图片和接口请求全部经过 |
| 翻译 | 翻译服务：谷歌免费接口（默认，无需密钥）/ DeepL / 微软 Azure / 百度翻译开放平台 / LibreTranslate / AI 翻译（选服务商：内置九家只填 API Key，自定义填地址 + Key + 模型名）/ 自定义接口，各自填密钥或地址 |
| 维护 | 同步点赞记录；诊断信息 |

- 维护项是动作而非开关，点击立即执行，不需要保存，也不关闭设置页
- 保存设置只在推荐候选真正受影响（排除已看、老片穿插改动且当前在推荐流）或代理改动时重新加载列表，其余设置直接应用到当前卡片，不打断播放
- 诊断信息写成 txt 文件（保留最近 5 份），可复制或直接以文件形式分享到其它应用；只记录异常、退出原因和加载线索，不记录账号或视频列表，不自动上传

## 推荐算法

推荐页不直接照搬某一个官方榜单，而是从站内存档抽样、本地打分排序后再按位置插入关注更新和老片。

### 站内规模

| | |
| --- | --- |
| 按发布时间翻到底 | 第 10147 页（网页端一页 32 条） |
| 全站视频总数 | 约 32.5 万 |
| 换算成 App 的 36 条一页 | 约 9000 页 |
| 最早的投稿 | 2014 年 3 月 |
| 近期新增速度 | 每月约 6000 条 ≈ 167 页 |

一千多页只覆盖最近半年；早年的更新速度远低于现在，越靠后的页一页覆盖的时间越长。

### 候选来源：在整个存档里抽页

每一轮刷新都在各来源的存档里随机抽页：

| 来源 | 抽页范围 | 说明 |
| --- | --- | --- |
| 关注作者的更新（`/videos?subscribed=true&sort=date`） | 第 0 页 + 最多 200 页 | 首页保证新，往后是没看过的存量更新 |
| 最新投稿（`sort=date`） | 第 0 页 + 最多 1100 页（约半年） | 上限还受服务端回报的总页数约束；更老的视频只作为老片穿插，抽更深的页只会被分流 |
| 流行（`sort=popularity`） | 第 0 页 + 最多 60 页 | 越靠后越老、越没人看，不再往深取 |
| 热门（`sort=trending`） | 第 0 页 + 最多 6 页 | 轮换快 |
| 本月 / 上月点赞榜（`sort=likes&date=yyyy-MM`） | 前 3 页随机 | 近期里真正受欢迎的作品；按时间随机抽到的近期视频大多点赞很少，这一路把“赞多的”补进来。若服务端回报的总数是全站量（说明过滤没生效），本次结果丢弃并停用 |
| 个性化召回 | 标签 `tags=` 前 2 页随机、作者 `user=` 第 0 页 | 画像里权重最高的 2 个标签（≥ 1.5）和 1 位作者（≥ 2.5，按作者 id） |

- 抽页概率偏向靠前（页码按均匀随机数的立方缩放）：新内容优先，尾巴足够长
- 第 0 轮固定包含各榜单首页，冷启动不受影响；没看过的候选不够时继续抽新页，而不是往后挪一页
- 两次刷新不会落在同一批页上
- **总页数来自接口回传的 `count`**：每轮第 0 页请求都会带回总条数，抽页范围随之更新；表中的数字是策略上限，实际取两者中较小者
- 退路：服务端不回报 `count` 时，某页请求成功却为空即把该榜单上限压到该页以下；超时和失败不算数，并有下限保护

### 关注的作者按位置插入

关注作者的更新不参与打分加权，而是**每 5 条未关注内容配 1 条关注作者的更新**（占比 1/6），插在这一组内的随机位置。关注更新不足以铺满时自动拉大间隔，均匀散布在最终显示的那一段里；一条都没有时列表原样返回。关注列表每 6 小时在后台更新一次。

### 近期优先，老片按间隔穿插

推荐流的**主体只放发布不满半年的视频**（接口没给发布时间的也算近期）。候选里抽到的更老的视频不直接进流，而是并入老片池。近期视频不足 24 条时才用老的补足，不给空页。

老片池 = 专门抓的老片 + 候选里分流出来的老视频。专门抓的老片来自 `sort=likes` 第 8 页以后随机抽的一页，只取发布超过半年、未点赞、未收藏的（开启排除已看时也排除已看），排在分流出来的老视频前面。在主体之上，**每 12 条一组，组内随机位置塞 1 条老片**；老片请求失败或超时不影响首屏。间隔可在设置中调整；关闭穿插后老视频不再出现在推荐流里。

### 打分

- 来源权重与该来源里的排名
- **站方质量分**：平滑点赞率为主、热度为辅。点赞率按贝叶斯平滑（先验 400 次播放、5% 点赞率），相对平均水平取对数（限幅 −1.5～2.5）×1.6，再加 `0.5·ln(赞+1) + 0.12·ln(播放+1)`；十次播放五个赞压不过十万播放一万赞，同等热度下点赞率高的靠前，纯点赞数的老片优势被削弱
- 视频新鲜度（衰减曲线较缓，存档深处的视频仍有机会）
- **本地画像**（可正可负，限幅 −6～8 后 ×0.38）：作者按名字和 id 两套键、标签按名字累计权重
- 少量稳定扰动，避免结果僵化
- 不按页码衰减：深页不比首页差，只是更老，由新鲜度评判

### 行为信号与画像

| 行为 | 权重 | 条件 |
| --- | --- | --- |
| 点赞 | +2.0 | |
| 收藏 | +1.4 | |
| 下载 | +1.1 | |
| 播完 | +0.7 | |
| 看得久 | +0.8 | 真播满 45 秒或看过一半，划走时记 |
| 快速划走 | −0.5 | 播放器 READY 过、没报错、起播不到 4 秒且进度不到 20%，且是翻页划走（切后台、进内部页面不算） |
| 官方历史点赞（种子） | +1.2 | 同步官方点赞时把最近 500 条种进画像，每条只记一次 |

- 标签权重按作者权重的 0.45 累计
- 所有行为按时间衰减（一个月折半），最近 45 分钟内的再 ×2.5 作为**当前兴趣**（官方点赞种子除外）；连着看几条同一主题，后面的推荐马上跟上
- 行为表保留最近 3000 条，算画像读最近 2000 条
- 播放失败后划走不计负反馈，网络问题不污染画像

### 多样性

同一作者在任意连续 5 条里最多出现一次：打分高的作者的其余作品往后挪，各自内部顺序不变。

### 排除已看

开启后，`seen_videos` 中的视频在下一次生成推荐列表时被过滤。候选按“没看过 / 看过但没点赞 / 已点赞收藏”分三档：没看过的不足 12 条时继续抽页，仍不够时补看过但没点赞的，已点赞收藏的只在没有别的可推时使用，不会给出空页面。

Iwara 官方点赞会完整同步进 `seen_videos`（服务端一页最多 50 条，后台按页读完），每 6 小时一次，也可在设置中手动触发。

诊断信息中记录本次刷新抽到的页码和用到的个性化召回。

## 技术说明

### 技术栈

- Kotlin，ViewPager2 竖滑流
- AndroidX Media3 / ExoPlayer 1.11.0，CacheDataSource / SimpleCache 磁盘缓存
- OkHttp、Coil
- SQLiteOpenHelper 本地数据库；AndroidX Security Crypto 加密会话
- Android ImageDecoder / AnimatedImageDrawable 播放内置 GIF 动画（minSdk 28，无第三方动画库）；两段素材均为 560×560、70ms/帧（点赞 26 帧，收藏 35 帧），按屏幕显示尺寸解码
- Android DownloadManager、Picture-in-Picture、FileProvider
- GitHub Releases 应用内更新

### 播放与缓冲

- 竖滑流缓冲上限 25 秒（ExoPlayer 默认 50 秒），起播缓冲 1.2 秒；画质由视频源决定，不受影响
- 当前视频稳定 READY 后，在网络空闲阶段预缓存后续视频的前约 2 MB：Wi-Fi 预缓存两条，移动数据或下行低于 4 Mbps 只预缓存一条
- 播放器与预缓存共用同一 CacheDataSource，约 256 MB LRU 上限；多个 Activity 共用同一个 SimpleCache
- 播放器 decoder fallback

### 生命周期

- `onPause` 只暂停不释放播放器（半透明界面盖上时页面仍可见）；`onStop` 才释放解码器
- 分享：目标应用以显式 Intent 通过 ActivityResult launcher 拉起（不经过系统选择器），期间标记为“正在打开内部页面”，不触发自动小窗，也不暂停播放；主界面 `windowSoftInputMode="adjustNothing"`，评论输入层是独立 Dialog 窗口，键盘只顶起它
- Activity 销毁时网络客户端在后台清理，不在主线程关闭 TLS 连接
- 请求提交与关闭共用同一生命周期保护，丢弃已关闭页面的迟到结果
- 各子页面使用 AndroidX 返回分发，系统按键与手势共用同一返回路径

### 评论面板几何

面板高度 = 屏幕高度 − 顶栏高度 − 画面按 fit 铺满宽度时的高度，限制在屏幕高度的 45%～70% 之间；画面区域顶边 = max(顶栏底边, 屏幕高度 − 面板高度 − 画面高度)。横屏视频画面比区域矮时顶边下移贴住面板；竖屏视频画面比区域高时从顶栏底边开始并按高度缩小。两种情况画面底边都与面板顶边重合。

### 网络

- 手动代理通过 `ProxySelector.setDefault` 设为进程级默认，OkHttp、Media3 的 HTTP 数据源和 Coil 全部经过；本机地址不走代理
- 连接层错误（`Connection reset`、超时、DNS 失败、TLS 握手失败）在视频流的错误提示和诊断中统一翻译为“连不上 Iwara，请检查代理 / VPN 是否对本应用生效”。这类错误表示 Iwara 在当前网络下不可直达，不是应用故障

### 界面

- 播放主界面深色沉浸式；登录 / 搜索 / 设置弹窗浅蓝白色主题，主按钮带 OEM 主题兼容兜底
- 浏览历史、作者主页、搜索结果使用浅蓝卡片列表
- 点赞 / 收藏使用圆润的爱心与五角星矢量图标，同尺寸；画质 / 下载 / 小窗按钮带文字说明
- 专属 launcher 图标：黄色底、蓝色渐变的圆角播放三角与波浪，自适应图标（前景位图在 `mipmap-*/ic_launcher_foreground.png`，原图在 `art/launcher-source.png`）

## 构建与发布

要求：JDK 17+、Android SDK 36、Gradle 8.13。

```bat
gradlew.bat assembleDebug
```

单元测试：`gradle :app:testDebugUnitTest`。设备测试（仅测试模拟器）：`gradle :app:connectedDebugAndroidTest`，参数 `-Pandroid.testInstrumentationRunnerArguments.backMode=key` 或 `gesture` 分别验证系统按键与手势返回；测试使用合成数据，不需要真实账号。

每次推送到 `main` 后 GitHub Actions 自动：

1. 配置 JDK / Android SDK / Gradle，运行单元测试
2. 构建 release APK，使用仓库内固定 keystore 签名并用 `apksigner verify` 验证
3. 上传 `IwaraFlow-signed-APK` Actions Artifact
4. 根据 `versionName` 创建或刷新对应 GitHub Release，并上传 `IwaraFlow-signed.apk` 供应用内更新下载

> 发布新版本时必须同时提高 `versionCode` 与 `versionName`，否则已安装相同版本号的客户端不会收到更新提示。
