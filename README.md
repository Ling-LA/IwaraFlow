# IwaraFlow

Android 原生的 Iwara 竖屏短视频流播放器，目标是提供类似短视频 App 的连续浏览体验。

## 当前功能

### 视频流

- 推荐 / 最新 / 流行 / 人气
- **最新**：直接使用 Iwara 官方 `sort=date`
- **流行**：直接使用 Iwara 官方 `sort=trending`
- **人气**：直接使用 Iwara 官方 `sort=popularity`
- **推荐**：IwaraFlow 本地推荐算法，对多个官方榜单候选重新打分排序
- 上滑下一条、下滑上一条
- 自动加载更多视频；推荐页翻页继续使用推荐算法候选，候选用完会重新生成一批
- 播放结束自动进入下一条
- **刷新推荐时排除已看视频**：只在重新生成推荐列表时过滤历史记录，不再在滑动过程中连续自动跳过
- **独立已看记录表**：已看视频 ID 持久化保存，数据库升级时自动迁移旧 history 数据
- **可播放验证**：视频进入推荐 / 最新 / 流行 / 人气 / 搜索列表前，先解析实际 CDN 播放源并进行 Range 探测；确认能返回媒体数据后才显示
- 冷启动优先验证较小候选窗口，缩短首次打开等待时间
- **首屏边验证边上屏**：最先通过可播放验证的前几条立即进入播放，其余候选在后台继续验证并自动补进列表，顺序不变
- 单条卡住的视频源或卡住的官方榜单请求都有时间预算，不再拖住整个冷启动

### 作者主页 / 关注 / 好友

- 点击视频作者名可进入作者主页
- 作者主页分页展示该作者作品
- 作者作品显示真实 Iwara 视频缩略图
- 不可播放作品保留在作者列表，并在缩略图上显示“仅限好友观看 / 没有权限 / 视频处理中 / 资源失效”等原因
- 点击作者列表中可播放视频后，进入仅包含该作者作品的竖滑播放流
- 作者作品播放流支持首尾循环
- 返回顺序：作者播放流 → 作者作品列表 → 实际进入作者页的页面；从已关注列表进入时先返回已关注列表
- Android 系统返回键 / 全面屏返回手势 / 页面返回按钮使用同一返回逻辑
- 关注状态同步 Iwara 官方数据
- 支持关注 / 取消关注作者
- 主菜单可查看 Iwara 官方“已关注用户”并进入作者主页
- 已关注列表按服务端返回的总数翻页读取，关注超过 50 位也会全部列出
- 支持发送好友申请 / 取消好友申请 / 删除好友
- 好友关系状态通过 Iwara 官方接口读取

### 播放器与预加载

- AndroidX Media3 / ExoPlayer
- 默认最高可用画质 / 原画
- 手动切换清晰度
- 单击播放 / 暂停
- 暂停时在视频标签下方显示进度条，可拖动跳转；同时隐藏信息栏和操作栏，避免拖动时误触点赞 / 下载 / 分享。播放时进度条隐藏、信息栏和操作栏恢复
- 双击点赞 + 爱心动画
- **按住视频约 0.45 秒临时 2× 加速，松手恢复 1×**
- 加速时显示 `2× 加速中`
- Android 画中画（PiP）
- 可设置切到后台自动进入画中画
- 右侧操作栏在小窗按钮下方新增分享按钮，可把视频链接转发到其它社交应用
- 作者主页右上角新增“分享作者”，转发作者名字、简介和主页链接
- 竖滑流缓冲上限 25 秒（默认 50 秒）：划走时浪费的流量少一半，起播缓冲 1.2 秒，弱网首帧更快；画质不受影响
- 播放器 decoder fallback
- 播放卡死 watchdog：检测到时间轴长时间不前进时自动重建播放源
- 切换视频后旧页面直接停止并释放 ExoPlayer，避免后台继续播放声音
- **全 App 单一播放所有权**：进入作者页 / 作者作品播放器等其他视频页面时会立即停止上一页面播放器，避免两个页面同时出声
- **Media3 磁盘预缓存**：当前视频稳定 READY 后，网络空闲阶段预缓存后面视频的前约 2 MB；Wi-Fi 预缓存下一条和下下条，移动数据或弱网只预缓存下一条
- 播放器与预缓存共用同一 CacheDataSource，滑到下一条时可以直接命中已经缓存的数据
- 预缓存使用约 256 MB LRU 上限，自动淘汰旧缓存
- 多 Activity 共用同一个 Media3 SimpleCache，避免重复打开同一缓存目录造成闪退

### Iwara 账号

- Iwara 登录：`/user/login` → `/user/token`
- Token 使用 AndroidX Security 加密存储
- 密码不保存到本地
- Iwara 点赞真实同步：`POST / DELETE /video/{id}/like`
- Iwara 点赞记录：`/favorites/videos`
- Iwara 关注同步
- Iwara 好友关系同步

### 本地收藏

IwaraFlow 的星形收藏是**纯本地收藏**，与 Iwara 官方点赞完全分离：

- `♥` 心形：Iwara 官方点赞，会同步服务端
- `★` 星形：IwaraFlow 本地收藏，仅保存在当前设备 SQLite 数据库

点击点赞不会再同时点亮本地收藏。

### 浏览历史

- SQLite 本地浏览历史
- 保存最近观看的视频
- 保存最后播放位置、视频时长和是否基本看完
- 独立 `seen_videos` 表永久记录推荐系统使用的“已看视频 ID”
- 浏览历史使用独立卡片列表展示
- 本地收藏也有独立列表

### 搜索与下载

- 搜索结果显示在**独立的搜索结果页**，不再直接顶掉首页视频流
- 搜索页采用与作者主页相同的浅蓝卡片列表风格，顶部可继续修改关键词重新搜索
- 三个结果标签页分别展示：
  - **视频名**：`/search?type=videos&query=...`
  - **标签**：按 Iwara 视频标签检索 `/videos?tags=...`；空格、逗号、顿号分隔的多个词表示“同时带这些标签”，搜不到时再按下划线、连写当成一个标签重试
  - **作者名**：`/search?type=users&query=...`，显示作者头像并可直接进入作者主页
- 视频结果保留不可播放作品并显示原因，可播放的点开后在搜索结果内竖滑播放
- 返回顺序：搜索视频流 → 搜索结果列表 → 进入搜索的页面
- 使用 Android DownloadManager 下载
- 下载前可选择视频清晰度

## 推荐算法

推荐页不会直接照搬某一个 Iwara 官方榜单。

候选视频来自：

- `trending`，基础权重 3.3
- `popularity`，基础权重 2.8
- `likes`，基础权重 2.1
- `views`，基础权重 1.6

每组抓取前 36 条，同一个视频同时进入多个榜单时会得到额外加分。

随后综合：

- 官方榜单来源权重
- 榜单排名
- 点赞数
- 播放量
- 视频新鲜度
- 本地作者偏好
- 本地标签偏好
- 点赞、收藏、完整观看、下载等本地行为
- 少量稳定扰动，避免推荐结果完全僵化

开启“刷新推荐时排除已看视频”后，`seen_videos` 中的已看视频会在**下一次推荐列表生成时**被直接过滤，不会在当前列表里反复触发自动跳过。

Iwara 官方点赞会完整同步进 `seen_videos`：启动后台按页读完整个点赞列表（服务端一页最多 50 条），每 6 小时同步一次，主菜单的**同步点赞记录**可以手动触发。之前只读第一页，点赞超过 50 个的账号，更早的点赞会一直回到推荐里。

## GitHub Actions APK / Release

仓库包含自动 Android 构建与发布工作流。

每次推送到 `main` 后会自动：

1. 配置 JDK / Android SDK / Gradle
2. 构建 release APK
3. 使用仓库内固定 keystore 对 APK 签名
4. 使用 `apksigner verify` 验证签名
5. 上传 `IwaraFlow-signed-APK` Actions Artifact
6. 根据 `versionName` 创建或刷新对应 GitHub Release
7. 将 `IwaraFlow-signed.apk` 上传为 Release 资产，供 App 内更新直接下载

> 发布新正式版本时必须同时提高 `versionCode` 与 `versionName`，否则已安装相同版本号的客户端不会弹出更新提示。
