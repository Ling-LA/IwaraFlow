# IwaraFlow

Android 原生的 Iwara 竖屏短视频流播放器，目标是提供类似短视频 App 的连续浏览体验。

## 当前功能

### 视频流

- 推荐 / 最新 / 流行 / 人气
- **最新**：直接使用 Iwara 官方 `sort=date`
- **流行**：直接使用 Iwara 官方 `sort=trending`
- **人气**：直接使用 Iwara 官方 `sort=popularity`
- **推荐**：IwaraFlow 本地推荐算法，每次刷新在整个站内存档里随机抽页取候选并重新打分排序
- 上滑下一条、下滑上一条
- 自动加载更多视频；推荐页翻页继续使用推荐算法候选，候选用完会重新生成一批
- 播放结束自动进入下一条
- **刷新推荐时排除已看视频**：只在重新生成推荐列表时过滤历史记录，不再在滑动过程中连续自动跳过
- **独立已看记录表**：已看视频 ID 持久化保存，数据库升级时自动迁移旧 history 数据
- **可播放验证**：视频进入推荐 / 最新 / 流行 / 人气 / 搜索列表前，先解析实际 CDN 播放源并进行 Range 探测；确认能返回媒体数据后才显示
- 冷启动优先验证较小候选窗口，缩短首次打开等待时间
- **首屏边验证边上屏**：最先通过可播放验证的前几条立即进入播放，其余候选在后台继续验证并自动补进列表，顺序不变
- 单条卡住的视频源或卡住的官方榜单请求都有时间预算，不再拖住整个冷启动

### 作者主页 / 关注 / 好友

- 点击视频作者名可进入作者主页
- 作者主页分页展示该作者作品
- 作者作品显示真实 Iwara 视频缩略图
- 不可播放作品保留在作者列表，并在缩略图上显示“仅限好友观看 / 没有权限 / 视频处理中 / 资源失效”等原因
- 点击作者列表中可播放视频后，进入仅包含该作者作品的竖滑播放流
- 作者作品播放流支持首尾循环
- 返回顺序：作者播放流 → 作者作品列表 → 实际进入作者页的页面；从已关注列表进入时先返回已关注列表
- Android 系统返回键 / 全面屏返回手势 / 页面返回按钮使用同一返回逻辑
- 关注状态同步 Iwara 官方数据
- 支持关注 / 取消关注作者
- 主菜单可查看 Iwara 官方“已关注用户”并进入作者主页
- 已关注列表按服务端返回的总数翻页读取，关注超过 50 位也会全部列出
- 支持发送好友申请 / 取消好友申请 / 删除好友
- 好友关系状态通过 Iwara 官方接口读取

### 播放器与预加载

- AndroidX Media3 / ExoPlayer
- 默认最高可用画质 / 原画
- 手动切换清晰度
- 单击播放 / 暂停
- 暂停时在视频标签下方显示进度条，可拖动跳转；同时隐藏信息栏和操作栏，避免拖动时误触点赞 / 下载 / 分享。播放时进度条隐藏、信息栏和操作栏恢复
- 点赞 / 收藏按钮为圆润的爱心和五角星矢量图标，选中后填充上色
- 点赞、收藏、双击点赞都会播放动画，并且**播在点的那个位置**：点按钮就在按钮上播，双击视频就在手指落点播
- 动画素材为内置 GIF，由系统 `AnimatedImageDrawable` 解码（minSdk 28，不依赖第三方库），按屏幕实际尺寸解码以节省内存；解码失败时回退到内置的矢量动画
- **按住视频约 0.45 秒临时 2× 加速，松手恢复 1×**
- 加速时显示 `2× 加速中`
- Android 画中画（PiP）
- 可设置切到后台自动进入画中画
- 右侧操作栏在小窗按钮下方新增分享按钮，可把视频链接转发到其它社交应用
- 作者主页右上角新增“分享作者”，转发作者名字、简介和主页链接
- 竖滑流缓冲上限 25 秒（默认 50 秒）：划走时浪费的流量少一半，起播缓冲 1.2 秒，弱网首帧更快；画质不受影响
- 播放器 decoder fallback
- 播放卡死 watchdog：检测到时间轴长时间不前进时自动重建播放源
- 切换视频后旧页面直接停止并释放 ExoPlayer，避免后台继续播放声音
- **全 App 单一播放所有权**：进入作者页 / 作者作品播放器等其他视频页面时会立即停止上一页面播放器，避免两个页面同时出声
- **Media3 磁盘预缓存**：当前视频稳定 READY 后，网络空闲阶段预缓存后面视频的前约 2 MB；Wi-Fi 预缓存下一条和下下条，移动数据或弱网只预缓存下一条
- 播放器与预缓存共用同一 CacheDataSource，滑到下一条时可以直接命中已经缓存的数据
- 预缓存使用约 256 MB LRU 上限，自动淘汰旧缓存
- 多 Activity 共用同一个 Media3 SimpleCache，避免重复打开同一缓存目录造成闪退

### Iwara 账号

- Iwara 登录：`/user/login` → `/user/token`
- Token 使用 AndroidX Security 加密存储
- 密码不保存到本地
- Iwara 点赞真实同步：`POST / DELETE /video/{id}/like`
- Iwara 点赞记录：`/favorites/videos`
- Iwara 关注同步
- Iwara 好友关系同步

### 收藏

收藏（五角星）与点赞（爱心）是两件事，互不影响：

- **爱心**：Iwara 官方点赞，同步到服务端，网页端也能看到
- **五角星**：IwaraFlow 的收藏，存在本机 SQLite 数据库里

点击点赞不会同时点亮收藏。

> 界面上不再出现“本地收藏”“仅保存在本机”这类说法——容易被理解成“只是暂存、随时会丢”。
> 菜单和页面统一叫**我的收藏**，收藏 / 取消收藏也不再弹提示：星星填充与否本身就是反馈。

### 浏览历史

- SQLite 本地浏览历史
- 保存最近观看的视频
- 保存最后播放位置、视频时长和是否基本看完
- 独立 `seen_videos` 表永久记录推荐系统使用的“已看视频 ID”
- 浏览历史使用独立卡片列表展示
- 我的收藏、已下载也各有独立列表，三者共用同一套卡片布局

### 搜索与下载

- 搜索结果显示在**独立的搜索结果页**，不再直接顶掉首页视频流
- 搜索页采用与作者主页相同的浅蓝卡片列表风格，顶部可继续修改关键词重新搜索
- 三个结果标签页分别展示：
  - **视频名**：`/search?type=videos&query=...`
  - **标签**：按 Iwara 视频标签检索 `/videos?tags=...`；空格、逗号、顿号分隔的多个词表示“同时带这些标签”，搜不到时再按下划线、连写当成一个标签重试
  - **作者名**：`/search?type=users&query=...`，显示作者头像并可直接进入作者主页
- 视频结果保留不可播放作品并显示原因，可播放的点开后在搜索结果内竖滑播放
- 返回顺序：搜索视频流 → 搜索结果列表 → 进入搜索的页面
- 使用 Android DownloadManager 下载
- 下载前可选择视频清晰度
- 主菜单新增 **已下载**，布局与收藏页一致：
  - 下载走系统下载器，所以 App 只记“下过什么”，页面再问系统“现在怎么样了”
  - 已完成的条目点击后直接播放本地文件
  - 仍在下载 / 下载失败的条目在卡片上标出状态
  - 系统里已经查不到的（清空了下载列表、删掉了文件）点击后退回在线播放，不会点了没反应
  - 同一个视频的不同清晰度各算一条；重新下载同一清晰度会覆盖旧记录
  - 主页、作者页、旧版视频流三个下载入口都会记录，列表不会漏

### 应用内更新

- 启动 App 后后台检查 GitHub 最新 Release
- 自动检查间隔约 6 小时，避免频繁请求
- 主菜单提供 **检查更新** 手动入口
- 发现新版本后显示：当前版本、新版本号、更新内容
- 点击“立即更新”直接下载固定签名 `IwaraFlow-signed.apk`
- 下载完成后自动拉起 Android 系统安装界面
- Android 8+ 如未授权“安装未知应用”，会自动进入对应授权页面，返回 App 后继续安装
- 更新 APK 使用与现有安装包相同的固定签名，可直接覆盖升级

## 推荐算法

推荐页不会直接照搬某一个 Iwara 官方榜单。

### 候选从哪来：抽页，而不是永远看第一页

Iwara 每个月新增六千多个视频，按发布时间能一直翻到一千多页（第 1000 页已经是半年前），
十二年的存量更是看不完。所以“推荐不出视频”从来不是片源不够，而是取片源的方式不对：
早期版本每次刷新都从各个榜单的**第 0 页**开始拿，于是每次拿到的都是同一批最新的一两百条，
看过一遍就真的没了；候选不够时又只往后翻一页，面对一千多页的存量等于没动。

现在每一轮都在整个存档里**随机抽页**：

| 来源 | 抽页范围 | 说明 |
| --- | --- | --- |
| 关注作者的更新（`/videos?subscribed=true&sort=date`） | 第 0 页 + 1–40 页 | 首页保证新，往前翻是没看过的存量更新 |
| 最新投稿（`sort=date`） | 第 0 页 + 1–900 页 | 一页 36 条，抽到第 300 页约一个多月前，第 900 页约一年前 |
| 流行（`sort=popularity`） | 第 0 页 + 1–400 页 | 保证质量，同样不只看第一页 |
| 热门（`sort=trending`） | 第 0 页 | 轮换本来就快 |

抽页概率偏向靠前（页码按均匀随机数的平方缩放），所以新内容仍然优先，但尾巴足够长，
能摸到一年前的视频。**两次刷新不会落在同一批页上**。第 0 轮固定包含各榜单首页，冷启动速度不受影响；
没看过的候选不够时继续抽新的页，而不是往后挪一页。

> 更早的版本还会抓 `likes` 和 `views`，这两个是全站历史总榜——基本是一组固定不变的老视频，
> 拉它们只是白费一次请求，现在已经不取了。

### 关注的作者按位置插入，不靠权重

关注作者的更新**不参与打分加权**。曾经试过把订阅流设为最高权重来源、再给已关注作者的视频额外加分，
结果整屏刷出来全是已经关注的人——推荐页也就不成其为推荐了。

现在改成按位置定量插入：**每 5 条没关注过的内容配 1 条关注作者的更新**，占比固定为 1/6，
与打分高低无关。插在这一组里的哪个位置是**随机**的，可能是第 1 位、第 3 位，也可能压到第 6 位；
固定排在组尾会形成一眼看得出来的节奏。至于哪一条关注作者的更新排在前面，仍然由打分决定。

关注列表每 6 小时在后台更新一次，不占首屏。

### 打分用到什么

- 来源权重与该来源里的排名
- 点赞数、播放量
- 视频新鲜度（衰减放缓过：候选有一大半来自存档，按老曲线一个月前的视频就已经被压到几乎没分了）
- 本地作者偏好、本地标签偏好
- 点赞、收藏、完整观看、下载等本地行为
- 少量稳定扰动，避免推荐结果完全僵化

打分**不按页码衰减**——存档深处的页不比首页差，只是更老，老不老交给新鲜度那一项去评。

诊断信息里会记下本次刷新抽到的页码，便于排查“推荐又没视频了”是不是卡回了第一页。

### 排除已看是偏好，不是硬墙

开启“刷新推荐时排除已看视频”后，`seen_videos` 中的已看视频会在**下一次推荐列表生成时**被过滤，
不会在当前列表里反复触发自动跳过。

但过滤不会把页面清空。候选按“没看过 / 看过但没点赞 / 已点赞收藏”分三档，
没看过的不足 12 条时先继续抽页去找，仍然不够就补上看过但没点赞的，
已点赞收藏的只在实在没别的可推时才用——宁可给看过的，也不给一个空页面。

Iwara 官方点赞会完整同步进 `seen_videos`：启动后台按页读完整个点赞列表（服务端一页最多 50 条），每 6 小时同步一次，主菜单的**同步点赞记录**可以手动触发。之前只读第一页，点赞超过 50 个的账号，更早的点赞会一直回到推荐里。

## GitHub Actions APK / Release

仓库包含自动 Android 构建与发布工作流。

每次推送到 `main` 后会自动：

1. 配置 JDK / Android SDK / Gradle
2. 构建 release APK
3. 使用仓库内固定 keystore 对 APK 签名
4. 使用 `apksigner verify` 验证签名
5. 上传 `IwaraFlow-signed-APK` Actions Artifact
6. 根据 `versionName` 创建或刷新对应 GitHub Release
7. 将 `IwaraFlow-signed.apk` 上传为 Release 资产，供 App 内更新直接下载

> 发布新正式版本时必须同时提高 `versionCode` 与 `versionName`，否则已安装相同版本号的客户端不会弹出更新提示。

**点赞 / 收藏动画**

- 动画改为播在**点的那个位置**：点按钮就在按钮上播，双击视频就在手指落点播，不再固定在屏幕正中央

- 点赞动画只在请求真正发出去时才播——未登录点击会直接弹登录框，不会先庆祝一遍

**素材处理**

- 收藏素材原件在星身上斜压了一道水印。它被画成比星身黄暗一档的颜色，因此只出现在色块内部、从不落在抗锯齿描边上——正好成为区分依据：水印在 GIF 调色板里自成若干条目，把这些条目指回底色即可，**一个像素都不用重新编码，透明度零改动**。每帧 2200–2900 个水印像素降到 0–11 个
- 单元测试会读取打包后 GIF 的调色板，防止以后重新导入素材时漏掉去水印这一步
- 裁掉了像素完全重复的帧（仅裁 disposal 不携带状态的帧，并逐帧校验合成结果一致）：点赞 50 帧 / 2000ms → 26 帧 / 1040ms（原素材尾部有整整 1 秒静止），收藏 40 帧 / 2800ms → 35 帧 / 2450ms
- 收藏 / 取消收藏不再弹提示：动画和星星填充状态本身就是反馈

### v0.7.16

**推荐算法：不再永远只看第一页**

- 起因：Iwara 每月新增六千多个视频，按时间能翻到一千多页，而旧逻辑每次刷新都从各榜单第 0 页开始取，于是每次都是同一批最新的一两百条；候选不够时又只往后翻一页，对一千多页的存量毫无意义
- 改为每轮在整个存档里随机抽页，概率偏向靠前（新内容仍优先），但尾巴可达一年前；两次刷新不会落在同一批页上
- 补量时继续抽新页，并翻关注作者的**存量**更新，而不是只看最新一页
- 去掉按页码的打分衰减——深页不比首页差，只是更老，交给新鲜度评判
- 新鲜度衰减放缓：原曲线下一个月前的视频几乎已经没分了
- 诊断信息记录本次抽到的页码

**点赞 / 收藏按钮（本版为矢量图标与自绘动画，GIF 于 v0.7.17 接入）**

- 动画位置从屏幕正中央改到按钮 / 手指位置
