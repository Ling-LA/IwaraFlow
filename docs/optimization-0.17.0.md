# 0.17.0 客户端缺陷复核与优化

基线：0.16.14（413d691）；范围：Android 客户端、数据存储、网络请求、播放和发布流程。不涉及云端服务器部署。按“先实现缓存恢复 → 复核 → 修复 → 本地模拟器 → 推送发布”的顺序执行。

## 复核结果

工程评估：84/100，本地发布前置检查已通过；真实账号与长时真机行为仍有验证边界，自动发布还必须通过 CI 跨系统门槛。

发现并处理以下问题；没有以大范围重构替代缺陷修复。

| 优先级 | 缺点 / 触发条件 | 处理与验证 |
| --- | --- | --- |
| P1 | 冷启动丢弃内存中的推荐队列，磁盘预缓存失去入口 | 加密保存后续最多 2 个候选；新进程验证实际磁盘缓存后恢复，后台续接新推荐；Android 16 两阶段 instrumentation + force-stop 验证不同 PID 恢复及真实 Media3 首帧 |
| P1 | 持久化推荐若不隔离身份 / 私密浏览，会恢复错误账号或已屏蔽内容 | 绑定账号和历史 / 兴趣范围；恢复时重新检查已看、收藏、屏蔽；切账号、开启隐私、切数据范围、清理历史 / 缓存时失效；真实 Keystore / SQLite 设备回归 |
| P1 | 直接持久化短期播放地址可能失效，也可能泄露带签名 URL | 仅进入 Android Keystore 加密存储；最多 64 KiB、最多 2 条、12 小时寿命；完整缓存可直接读；部分缓存的地址过期则重解析，同文件稳定缓存键复用已下载部分；时间策略和缓存键回归 |
| P2 | 调整容量调用清理，连扩大容量也删除闲置缓存 | 改为按新容量淘汰超限的旧片段，保留其它缓存；容量与缓存读取回归 |
| P2 | 磁盘不足时播放器绕过已有缓存，反而重新走网络 | 低存储使用只读缓存数据源；已有缓存可读，未缓存部分联网但不写盘；实际数据源读取计数及零新增缓存验证 |
| P2 | 初始化未结束时点击清缓存，操作被直接忽略 | 串行排队等待初始化完成后清理；保留播放所有者仍在使用的片段；初始化期间清理回归 |
| P2 | 恢复的完整缓存地址已过期时，画质选择可能只剩旧选项；迟到的画质回调可能在新视频弹出 | 不阻塞缓存起播，点画质时刷新完整地址列表；回调校验当前视频和绑定代次，防止错位弹窗 |
| P2 | 启动恢复可能与切页、外部链接或后台状态冲突 | 请求序号与一次性回调约束；恢复超时退回正常启动；后台不启动延迟推荐补充；现有导航 / 暂停 / 分享链接回归 |

## 整体检查的边界

- 播放：前后台 / 内部页面保留暂停意图；控制区手势、横竖屏指引、弹幕去重、画质恢复、小窗返回继续纳入回归。
- 推荐与搜索：权重上限 / 衰减、多样性、已看及屏蔽过滤、多语言别名、空结果与真实异常区别，沿用现有回归；缓存队列只做短期承接，不固定整条推荐流。
- 数据：收藏写入回滚、按账号隔离、数据库迁移和备份导入验证；本次不改变数据库结构。
- 安全：登录与 AI 密钥仍仅存加密存储；系统备份排除偏好 / 数据库；HTTPS、非导出内部页面、诊断链接及 Bearer 脱敏继续有效。
- 上传与下载：上传归属校验、发布结果不确定时不自动重试、任务暂停及文件权限；无账号凭据时不执行真实投稿、点赞或评论。
- 发布：保留私密签名与证书轮换；CI 的 Android 28 / 33 / 36、旧版覆盖安装及旧密钥替换拒绝检查仍是自动发布前置条件。README 顶部仅保留本版更新。

## 限制与后续观察

- 只有已实际落盘的连续开头至少 64 KiB 才参与恢复；尚未写完的临时片段不能保证在系统直接杀进程后保留。
- 系统清理缓存、容量淘汰、12 小时过期、无未看候选或 Keystore 不可用时正常重新生成推荐。快照失效不会阻止软件启动。
- 部分缓存仍需网络继续播放；重新解析只有同视频 / 同画质 / 同文件可复用，文件版本变化不会错误拼接。
- 官方接口的实时可用性、付费 AI 翻译质量、真实账号上传结果、真实手机长时发热耗电不能由中性模拟器回归替代，不承诺全网络条件下零等待。
- 现存文案国际化 / 弃用 API lint 警告与大型 Activity 的维护成本仍需渐进处理；本版没有用全局抑制或重写来隐藏它们。

## 回退方式

不迁移数据库。若发布后需要禁用缓存恢复，可发布更高 versionCode 的修正版，让冷启动回到普通推荐请求并清除 warm_recommendation_queue；保留历史、收藏和媒体缓存。Android 不支持普通覆盖降级，不指导用户卸载而丢失数据。
