# 0.19.0 标题、简介与推荐流

## 原有问题

此前主要依靠作者、标签、观看与互动、热度和来源打分。标题仅用于展示及搜索，简介不形成兴趣特征。标签缺失时，相近题材难以被识别；作者惯用的宽泛标签也可能掩盖作品差异。节日曝光又会产生观看记录，活动结束后可能经由自动标签偏好继续获得推荐。

## 本次实现

1. 保留原有召回、热度和显式兴趣规则，在候选排序中补充本地文字信号。标题最多分析 180 字符、简介最多 1600 字符；只使用已经取得的内容，不为推荐逐条抓取详情。
2. 已知中英日韩别名归一化为同一概念，处理拉丁、汉字、日文片假名、韩文等关键词。移除网址、邮箱、标记、推广行、常见制作与无信息词；同一概念不重复拆分，不和视频已有标签重复计分。
3. 结合最近 2000 条行为，从观看、完整观看、点赞、收藏、关注及取消/跳过中积累证据；相同视频和行为只取最新记录，单视频贡献限幅。至少两个视频、两个作者支持才形成特征；没有显式正向互动时至少三个视频。高频模板词降权或排除，但不会因长期反复出现就丢弃明确点赞、收藏等偏好或负向反馈。
4. 简介贡献为标题的四分之一，避免长篇推广或统一模板压倒作品标题。词权重 30 天半衰减，最多保留 256 项。正负得分分别限幅，再纳入原有有界画像分数，不覆盖屏蔽、不感兴趣等明确选择。
5. 文字匹配较强且符合兴趣理由间隔时显示标题/简介相关理由。来源、关注更新、探索、老片等原有理由仍可出现，不能每条都标成“猜你喜欢”。
6. 数据库由 12 升到 13，为互动保存文字特征。旧互动可从已有浏览历史/本地收藏补取标题，不伪造旧简介，不新增互动、不刷新旧行为时间。账号隔离、无痕和清空推荐画像沿用既有规则。
7. 节日结束后，正向自动标签、文字偏好和节日候选来源停止生效，旧缓存里的节日来源与理由也清理。手动选择节日兴趣仍有效；负向标签偏好仍保留。

## 为什么不直接提高所有文字匹配权重

标题可能夸大，简介常包含相同的推广和制作名单。少量相似词不能代表用户真正想看；只提高命中分会扩大这些误差。因此将它作为有限的补充信号，要求跨视频、跨作者证据并保留时间衰减，明确收藏、屏蔽和既有标签信号仍优先。

## 边界

- 这是本地关键词模型，不是 AI 对视频画面或长文本的语义理解，不调用付费模型，也不上传个人画像。
- 列表接口没有简介时，该候选只能使用标题；只有已经获取的简介参与。跨语言识别主要依靠已知别名，未知专有名词不保证合并。
- 旧版本没有记录的简介无法补学。真实推荐满意度需要后续使用反馈，自动测试只能验证规则、限幅、隔离和排序行为。
- 多语言搜索另外增加名称短语保留、词边界和上下文校验。无法确认的短名称保留原文，AI 模式也不能用字面翻译替换已核实名称，优先减少错搜而非凑齐四语。
