# 0.18.4 三连与长按动画验证

## 行为

画面中间区域长按由双连改为点赞、收藏、关注三连；普通播放和竖屏全屏保持上中下分区，横屏全屏保持左中右分区。总时间仍为 1.5 秒，系统长按阈值（至少 450ms）前不显示进度动画。松手、移动、取消触摸或离开播放模式会停止尚未完成的操作。

新图标为 64 单位画布上的竖起大拇指矢量，显示在 96dp 方形区域中，只有透明背景、图标、淡色圆环轨道和顺时针进度；原区域为 248×144dp。长按点赞按钮仍为双连，收藏按钮长按仍打开收藏夹。

三连等待官方操作确认后继续；已点赞、已收藏、已关注不取消。关注失败保留已确认的点赞和收藏并报告部分完成，自己的作品不关注自己；关注按钮已有请求时不覆盖它。账号切换后不接受旧会话的回调。不会发送真实账号测试点赞、收藏或关注。

同一作者多个视频的三连通过 API 层共用确认结果，按账号、登录会话和作者隔离，串行处理并发关注。在 5 分钟确认窗口内避免重复提交；窗口过后重新读取官网状态，已关注直接成功。若读取与提交之间其他页面已完成关注，或提交确认丢失，会再次核实相同作者的关注状态；核实成功才视为成功，不把真实网络 / 权限错误静默吞掉。手动取消关注立即更新确认记录，后续三连可以重新关注。

## 卡顿路径与处理

- 原长按圆环使用每 16ms 的 Handler 任务，与实际屏幕刷新不同步。现在使用 Choreographer 驱动绘制，独立计时器保证慢帧不会延长完成时间。
- 原点赞 / 收藏每次触发都会在 UI 线程调用 ImageDecoder 解码 GIF。现在在单个后台线程准备，每个已挂载动画视图复用素材；尚未准备好时立即显示矢量反馈。
- 快速点击不再给两个按钮添加长按圆环；图标和着色相同时不重复设置资源。
- GIF 复用的快速开始 / 停止测试发现 Android 已排队的结束回调与清空回调列表存在竞争。改为每份素材只注册一次回调，停止时取消引用，旧结束消息不能隐藏新一轮动画。

## 验证

本地全量单元测试 728 项通过，最终提交的 CI 全量单元测试亦通过。新增 10 项关注接口测试覆盖官网已关注、跨页面重复三连、并发请求去重、手动取消后重新关注、重复响应核实、真实失败可重试、账号切换、作者身份核对及缺少用户名的情况。

本地 Android Lint 为 0 错误、341 警告；Debug 和 R8 Release 构建成功。Android 16 模拟器完成 23 项常规设备用例验证；2 项真机界面抓取 / 宣传录制用例按设计跳过。覆盖长按取消与重复触发、设置往返、暂停保持、横竖屏指引、收藏管理以及过期地址预缓存恢复。最终安装包的动画专项再次通过。

动画专项在同一中性页面比较原同步 GIF 解码与新缓存触发，每种路径采样 8 次。最终代码复测结果：原解码中位数 2.767ms，新触发中位数 0.326ms，最大 1.230ms；动画阶段记录 243 帧，软件渲染模拟器的帧耗时 P95 为 50.619ms。此处只证明触发路径移除了同步解码并正确复用素材，不能据此声称整体播放帧率提升或所有设备不再卡顿。

设备测试使用中性页面，无真实内容提交。本次没有连接实体手机。
